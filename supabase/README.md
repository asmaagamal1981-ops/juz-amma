# إعداد Supabase لتطبيق «رحلة حفظ جزء عمَّ»

هذا الدليل يشرح تشغيل الحسابات والتقدم السحابي في `kids.html` خلال ٥ دقائق.

---

## 1) إنشاء المشروع

1. ادخل إلى <https://supabase.com/dashboard> وأنشئ مشروعًا جديدًا (اختر أقرب منطقة).
2. من **Project Settings → API** انسخ:
   - **Project URL** مثل `https://abcdefghijklm.supabase.co`
   - **anon / publishable key** (المفتاح الطويل الذي يبدأ عادة بـ `eyJ...` أو `sb_publishable_...`)

> ⚠️ **لا تنسخ `service_role` أبدًا** إلى الموقع. هذا المفتاح يتجاوز كل سياسات الحماية ويجب أن يبقى سرًّا في الخادم فقط.

---

## 2) إنشاء الجداول وسياسات الأمان

1. افتح **SQL Editor → New query**.
2. انسخ كامل محتوى [`schema.sql`](./schema.sql) والصقه ثم اضغط **Run**.

سيُنشئ:

| العنصر | الوظيفة |
|---|---|
| `public.kids_profiles` | اسم الطفل، صورة رمزية، ورد يومي، ونوع الدخول. |
| `public.kids_progress` | كل التقدم في عمود `jsonb` واحد (أوراد، اختبارات، نجوم، أوسمة، جوائز، شهادات، أيام). |
| فهارس + triggers | منع تكرار اسم الدخول وتحديث `updated_at` تلقائيًا. |
| سياسات **RLS** | كل مستخدم يقرأ ويكتب **صفّه فقط**؛ الزائر غير المسجّل لا يرى شيئًا. |
| `kids_delete_account()` | دالة آمنة (`SECURITY DEFINER`) تسمح للمستخدم بحذف حسابه نهائيًا. |

للتحقق بعد التنفيذ:

```sql
select tablename, rowsecurity
from pg_tables
where schemaname = 'public' and tablename like 'kids_%';
```

يجب أن تكون `rowsecurity = true` للجدولين.

## 3) ضبط تسجيل الدخول

من **Authentication → Sign In / Providers → Email**:

- ✅ **Enable Email provider**.
- ❌ **Confirm email = OFF** (مهم جدًا).
  التطبيق يستخدم بريدًا داخليًا مشتقًا لأصحاب أرقام الهواتف، ولا يمكنهم استلام رسالة تأكيد. تعطيل التأكيد يجعل التسجيل يعمل فورًا للجميع.

من **Authentication → URL Configuration**:

- **Site URL**: `https://asmaagamal1981-ops.github.io/juz-amma/`
- أضف إلى **Redirect URLs**:
  - `https://asmaagamal1981-ops.github.io/juz-amma/kids.html`
  - `http://localhost:8765/kids.html` (للتجربة المحلية)

> هذه الروابط لازمة لخاصية «نسيت كلمة المرور؟» بالبريد.

### كيف يعمل الدخول برقم الهاتف؟

Supabase Auth يعتمد على البريد. لذلك يحوّل التطبيق رقم الهاتف إلى بريد داخلي ثابت:

```
p<الأرقام فقط>@phone.juz-amma.app
مثال: 0501234567  →  p0501234567@phone.juz-amma.app
```

- الرقم نفسه يعطي دائمًا نفس البريد، فيعمل الدخول من أي جهاز.
- هذا البريد وهمي ولا يُرسل إليه شيء؛ لذلك **يجب تعطيل تأكيد البريد**.
- استعادة كلمة المرور بالبريد متاحة لحسابات البريد الحقيقية فقط. لحساب الهاتف، غيّر كلمة المرور من **الإعدادات ← كلمة المرور** داخل التطبيق.

## 4) وضع المفاتيح في الموقع

افتح [`../supabase-config.js`](../supabase-config.js) واملأ:

```js
window.KIDS_SUPABASE = {
  url: 'https://abcdefghijklm.supabase.co',
  anonKey: 'eyJhbGciOi...'
};
```

ثم ارفع الملف مع بقية الموقع. لا حاجة لأي build أو npm.

**بديل أفضل (إبقاء المفتاح خارج المستودع):** اترك `supabase-config.js` كما هو (قيم مؤقتة)، وأضف في المستودع:

**Settings → Secrets and variables → Actions**:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`

سير النشر `.github/workflows/pages.yml` سيولّد `_site/supabase-config.js` من السرّين تلقائيًا. هذا لا يغيّر أن المفتاح سيظهر في المتصفح بعد النشر — وهذا طبيعي — لكنه يمنع ظهوره في تاريخ Git.

### لماذا يُعدّ نشر مفتاح `anon` آمنًا؟

- مفتاح `anon` مفتاح عام (publishable) مصمَّم للعمل في المتصفح.
- كل طلب يمر عبر سياسات **RLS**، فلا يستطيع أحد قراءة صفوف طفل آخر حتى لو عدّل الطلبات يدويًا.
- المفتاح الذي يجب إخفاؤه هو `service_role`، وهو غير مستخدم في هذا المشروع إطلاقًا.
- لمزيد من الحماية: فعّل **Auth → Rate Limits**، وراجع **Logs** دوريًا، ولا تشارك كلمة مرور قاعدة البيانات.

## 5) اختبار سريع

1. افتح `kids.html` واختبر: حساب جديد ببريد → خروج → دخول.
2. سجّل حسابًا برقم هاتف ثم أعد الدخول به.
3. احفظ وردًا، أغلق المتصفح، ثم افتح من جهاز آخر وسجّل الدخول — يجب أن يظهر نفس التقدم.
4. **اختبار RLS بحسابين** (مهم): أنشئ حسابين A وB في متصفحين مختلفين، ثم سجّل الدخول بحساب A وافتح Console:

```js
// 1) يجب أن يعيد صفّ A فقط، وليس كل الصفوف
await window.__kids.client.from('kids_profiles').select('id, login, name');

// 2) استبدل <B-ID> بمعرّف حساب B: يجب أن يعيد [] (لا صلاحية قراءة)
await window.__kids.client.from('kids_profiles').select('*').eq('id', '<B-ID>');

// 3) محاولة تعديل صف B: يجب ألا تتأثر أي صفوف
await window.__kids.client.from('kids_profiles').update({ name: 'اختبار' }).eq('id', '<B-ID>');

// 4) محاولة إدخال تقدم لحساب B: يجب أن تفشل بسبب RLS
await window.__kids.client.from('kids_progress').insert({ user_id: '<B-ID>', data: {} });
```

5. جرّب **حذف الحساب** من الإعدادات ثم تأكد من اختفاء الصفوف من `auth.users` و`kids_profiles` و`kids_progress`.

---

## 6) ملاحظات تشغيلية

- **دون إنترنت**: يُحفظ آخر تقدم في ذاكرة المتصفح مؤقتًا، ويُزامن تلقائيًا عند عودة الاتصال. لا تغلق التطبيق قبل ظهور «☁️ محفوظ» إن كان الاتصال متقطعًا.
- **تعدد الأجهزة**: آخر حفظ يفوز (last-write-wins). لا تستخدم الجهازين في التعديل في اللحظة نفسها.
- **النسخ الاحتياطي**: زر «تصدير» في الإعدادات يبقى متاحًا ويعمل مع أي حساب.
- **البيانات القديمة**: الحسابات القديمة كانت محلية (PBKDF2). أنشئ حسابًا جديدًا ثم استورد ملف JSON الذي صدّرته من النسخة السابقة عبر **الإعدادات ← استيراد نسخة**. التطبيق يعرض أيضًا نقل التقدم القديم تلقائيًا إن وجده على المتصفح.
- **الحد المجاني**: مشاريع Supabase المجانية قد تتوقف مؤقتًا بعد فترة خمول؛ افتح لوحة التحكم لإعادة تنشيطها عند الحاجة.
