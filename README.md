# تفسير جزء عم | تدبّر وعمل 🌙

موقع تفاعلي لتفسير جزء عم (37 سورة) وفق منهج كتاب «القرآن تدبّر وعمل»:
معاني الكلمات • التفسير المختصر • وقفات تدبرية • العمل بالآيات • التوجيهات، مع اختبار تفاعلي وتتبع الإنجاز.

## الصفحات
| الملف | الوظيفة |
|---|---|
| `index.html` | الصفحة الرئيسية: بطاقات السور، منهجية التدبّر، ختمة التدبّر، اختبار سريع مدمج، وبانر تطبيق الأطفال. |
| `quiz.html` | **صفحة اختبارات التقييم المستقلة**: إعداد اختبار كامل، بنك الأسئلة، وتحليل النتائج. |
| `kids.html` | **تطبيق «رحلة حفظ جزء عمَّ» للأطفال**: حساب خاص، ورد حفظ ومراجعة، تسميع وتصحيح، جوائز وشهادات. |

## المعاينة محليًا
- للصفحات العادية (`index.html` و`quiz.html`) يمكن فتح الملف مباشرة في المتصفح.
- تطبيق الأطفال (`kids.html`) يحتاج **HTTPS أو `localhost`** لأن إنشاء الحساب يستخدم `crypto.subtle` (PBKDF2)، ويعمل عبر أي خادم ملفات ثابت. مثلًا:
  ```powershell
  # من جذر المشروع (Python 3)
  python -m http.server 8765
  # ثم افتح http://localhost:8765/kids.html
  ```

## صفحة الاختبارات (`quiz.html`)
- **بنك أسئلة تلقائي** (٣٣٣ سؤالًا) مبني من محتوى `surahs-data.js` في تسعة أنواع: المقاصد، معاني الكلمات (بسؤالين: من اللفظ إلى المعنى ومن المعنى إلى اللفظ)، الوقفات التدبرية، العمل بالآيات، عدد الآيات، ترتيب السور، المكية والمدنية، والآية المفتاحية.
- **إعداد الاختبار**: عدد الأسئلة (١–٨٠)، الأنواع المطلوبة، مستوى الصعوبة، النطاق (كل السور / مكية / مدنية / نطاق بأرقام السور / سور مختارة يدويًا)، المدة، درجة النجاح، الترتيب، والتصحيح الفوري.
- **أثناء الاختبار**: مؤقّت تنازلي (تسليم تلقائي عند انتهاء الوقت)، خريطة أسئلة للتنقل والتعليم، تصحيح فوري اختياري، واختصارات لوحة المفاتيح (`1–4` للاختيار، `Enter` للتالي).
- **بعد الاختبار**: نسبة النجاح، تحليل لكل نوع سؤال، مراجعة كل إجابة مع التعليل (تصفية: الكل / الخاطئة / غير المُجابة)، طباعة النتيجة، وسجل المحاولات (أفضل نتيجة، المتوسط) في التخزين المحلي.
- **مشاركة الرابط**: زر «نسخ رابط الاختبار» يشفّر الإعدادات في الرابط، فيفتحه أي طالب بنفس المواصفات.

## تطبيق «رحلة حفظ جزء عمَّ» للأطفال (`kids.html`)

تطبيق تفاعلي مستقل داخل الموقع، بهوية الموقع نفسها ووضعه الليلي، مصمّم للأطفال من ٦ سنوات فأكثر.

- **حساب خاص لكل طفل**: تسجيل بحساب (بريد إلكتروني أو رقم هاتف) وكلمة مرور. تُشتق كلمة المرور بـ **PBKDF2-SHA256** (١٢٠ ألف تكرار + salt عشوائي) عبر Web Crypto ولا تُحفظ نصًّا صريحًا. كل البيانات محلية في `localStorage` ولا تُرسل إلى أي خادم:
  `jz_users_v1` (الحسابات) • `jz_session_v1` (الجلسة) • `jz_data_v1_<id>` (بيانات كل طفل).
- **ورد يومي للحفظ الجديد + ورد للمراجعة**: خطة تلقائية تقسم الجزء من سورة الناس إلى النبأ بحسب مقدار الورد (٢–٨ آيات يوميًا)، وتُجدول المراجعة بنظام **تباعد متزايد** حسب نتيجة التسميع.
- **أربع طرق للتسميع والتصحيح داخل التطبيق**:
  1. تسميع آية بآية مع كشف الآية والتقييم الذاتي.
  2. ترتيب الكلمات (تصحيح تلقائي).
  3. أكمل الفراغ (تصحيح تلقائي).
  4. **تسجيل صوتي** للمقارنة بتلاوة الشيخ (مع بديل التصحيح الذاتي إذا رُفض إذن الميكروفون).
- **تلاوة الشيخ محمود خليل الحصري** لكل آية: `everyayah.com` مع بديل `cdn.islamic.network`، ومشغّل مع تكرار وتنقّل. الصوت يحتاج إنترنت، أما بقية التطبيق فيعمل دون اتصال بعد أول فتح.
- **تحفيز الأطفال**: نجوم لكل آية محفوظة واختبار، ١٦ وسامًا، مستويات، ٥ جوائز مع كود استلام، و**شهادة تقدير لكل سورة** تُرسم على canvas وتُحمَّل PNG أو تُطبع أو تُشارك.
- **إعدادات كاملة**: الاسم والصورة الرمزية، مقدار الورد، المؤثرات الصوتية، الوضع الليلي، تصدير/استيراد نسخة احتياطية JSON، إعادة تعيين التقدم، وحذف الحساب.

## تطبيق الجوال (PWA)

الموقع يعمل كتطبيق قابل للتثبيت على الجوال ويعمل **دون إنترنت** بعد أول فتح.

| الملف | الوظيفة |
|---|---|
| `manifest.webmanifest` | بيانات التطبيق: الاسم، الاتجاه RTL، الأيقونات، اختصارات الوصول السريع (رحلة الحفظ / الاختبارات / السور). |
| `sw.js` | Service Worker: يخزّن كل ملفات الموقع والخطوط، ويعمل دون اتصال. |
| `pwa.js` | تسجيل Service Worker + زر «ثبّت التطبيق» + تنبيه «توجد نسخة جديدة». |
| `icons/` | أيقونات 192 و512 وmaskable وapple-touch. |

**التثبيت على الجوال:**
- **أندرويد (Chrome/Edge):** يظهر شريط «ثبّت التطبيق» أسفل الصفحة، أو من القائمة ⋮ ← «تثبيت التطبيق».
- **آيفون/آيباد (سفاري):** زر المشاركة ← «إضافة إلى الشاشة الرئيسية».
- بعد التثبيت يفتح التطبيق بلا شريط عنوان، ومعه اختصارات: «رحلة الحفظ» و«الاختبارات» و«السور».

## النشر على GitHub Pages
يُنشر الموقع تلقائيًا باستخدام GitHub Actions عند كل تحديث لفرع `main`، كما يمكن تشغيل النشر يدويًا من تبويب **Actions**.

1. أنشئ مستودعًا على GitHub وارفع ملفات المشروع إلى جذر الفرع `main`، مع مجلد `.github/workflows` وملف `.nojekyll`.
2. في المستودع، افتح **Settings → Pages**، واختر **GitHub Actions** كمصدر للنشر.
3. ادفع التغييرات إلى `main` أو شغّل سير العمل **Deploy to GitHub Pages** يدويًا من **Actions**.
4. بعد نجاح التشغيل، افتح الرابط الظاهر في سجل سير العمل أو في **Settings → Pages**. عادةً يكون `https://USERNAME.github.io/REPOSITORY/`.

إذا كان اسم الفرع الافتراضي مختلفًا عن `main`، غيّر قائمة الفروع في `.github/workflows/pages.yml` لتطابقه. لا يحتاج الموقع إلى إعداد مسار أساسي خاص بالمستودع؛ جميع موارده محلية وبمسارات نسبية. التقدم والنتائج الأفضل محفوظة في التخزين المحلي للمتصفح الذي يستخدمه الزائر.
