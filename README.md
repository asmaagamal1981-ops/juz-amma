# تفسير جزء عم | تدبّر وعمل 🌙

موقع تفاعلي لتفسير جزء عم (37 سورة) وفق منهج كتاب «القرآن تدبّر وعمل»:
معاني الكلمات • التفسير المختصر • وقفات تدبرية • العمل بالآيات • التوجيهات، مع اختبار تفاعلي وتتبع الإنجاز.

## الصفحات
| الملف | الوظيفة |
|---|---|
| `index.html` | الصفحة الرئيسية: بطاقات السور، منهجية التدبّر، ختمة التدبّر، اختبار سريع مدمج، وبانر تطبيق الأطفال. |
| `quiz.html` | **صفحة اختبارات التقييم المستقلة**: إعداد اختبار كامل، بنك الأسئلة، وتحليل النتائج. |
| `kids.html` | **تطبيق «رحلة حفظ جزء عمَّ» للأطفال**: حساب خاص، ورد حفظ ومراجعة، تسميع وتصحيح، جوائز وشهادات. |

## المعاينة محليًا
- للصفحات العادية (`index.html` و`quiz.html`) يمكن فتح الملف مباشرة في المتصفح.
- تطبيق الأطفال (`kids.html`) يحتاج **HTTPS أو `localhost`** (للمصادقة والـ PWA)، ويحتاج ضبط Supabase أولًا كما في [`supabase/README.md`](supabase/README.md). مثلًا:
  ```powershell
  # من جذر المشروع (Python 3)
  python -m http.server 8765
  # ثم افتح http://localhost:8765/kids.html
  ```

## صفحة الاختبارات (`quiz.html`)
- **بنك أسئلة تلقائي** (٣٣٣ سؤالًا) مبني من محتوى `surahs-data.js` في تسعة أنواع: المقاصد، معاني الكلمات (بسؤالين: من اللفظ إلى المعنى ومن المعنى إلى اللفظ)، الوقفات التدبرية، العمل بالآيات، عدد الآيات، ترتيب السور، المكية والمدنية، والآية المفتاحية.
- **إعداد الاختبار**: عدد الأسئلة (١–٨٠)، الأنواع المطلوبة، مستوى الصعوبة، النطاق (كل السور / مكية / مدنية / نطاق بأرقام السور / سور مختارة يدويًا)، المدة، درجة النجاح، الترتيب، والتصحيح الفوري.
- **أثناء الاختبار**: مؤقّت تنازلي (تسليم تلقائي عند انتهاء الوقت)، خريطة أسئلة للتنقل والتعليم، تصحيح فوري اختياري، واختصارات لوحة المفاتيح (`1–4` للاختيار، `Enter` للتالي).
- **بعد الاختبار**: نسبة النجاح، تحليل لكل نوع سؤال، مراجعة كل إجابة مع التعليل (تصفية: الكل / الخاطئة / غير المُجابة)، طباعة النتيجة، وسجل المحاولات (أفضل نتيجة، المتوسط) في التخزين المحلي.
- **مشاركة الرابط**: زر «نسخ رابط الاختبار» يشفّر الإعدادات في الرابط، فيفتحه أي طالب بنفس المواصفات.

## تطبيق «رحلة حفظ جزء عمَّ» للأطفال (`kids.html`)

تطبيق تفاعلي مستقل داخل الموقع، بهوية الموقع نفسها ووضعه الليلي، مصمّم للأطفال من ٦ سنوات فأكثر.

- **حساب سحابي خاص لكل طفل**: تسجيل ببريد إلكتروني أو رقم هاتف وكلمة مرور عبر **Supabase Auth** (لا تُخزَّن كلمة المرور في الموقع إطلاقًا). لكل طفل صفّه الخاص في `kids_profiles` و`kids_progress`، ومحمي بسياسات **Row Level Security** تمنع أي طفل من رؤية بيانات غيره. يمكن الدخول من أي جهاز ومتابعة نفس التقدم.
  - رقم الهاتف يُحوَّل داخليًا إلى بريد ثابت `p<digits>@phone.juz-amma.app` لأن Supabase Auth يعتمد البريد؛ التفاصيل في [`supabase/README.md`](supabase/README.md).
  - تبقى نسخة مؤقتة على الجهاز (`jz_cloud_v1_<id>`) للعمل دون اتصال، وتُزامن مع السحابة تلقائيًا عند عودة الإنترنت. السحابة هي مصدر الحقيقة، وليست النسخة المحلية.
- **ورد يومي للحفظ الجديد + ورد للمراجعة**: خطة تلقائية تقسم الجزء من سورة الناس إلى النبأ بحسب مقدار الورد (٢–٨ آيات يوميًا)، وتُجدول المراجعة بنظام **تباعد متزايد** حسب نتيجة التسميع.
- **أربع طرق للتسميع والتصحيح داخل التطبيق**:
  1. تسميع آية بآية مع كشف الآية والتقييم الذاتي.
  2. ترتيب الكلمات (تصحيح تلقائي).
  3. أكمل الفراغ (تصحيح تلقائي).
  4. **تسجيل صوتي** للمقارنة بتلاوة الشيخ (مع بديل التصحيح الذاتي إذا رُفض إذن الميكروفون).
- **تلاوة الشيخ محمود خليل الحصري** لكل آية: `everyayah.com` مع بديل `cdn.islamic.network`، ومشغّل مع تكرار وتنقّل. الصوت يحتاج إنترنت، أما بقية التطبيق فيعمل دون اتصال بعد أول فتح.
- **تحفيز الأطفال**: نجوم لكل آية محفوظة واختبار، ١٦ وسامًا، مستويات، ٥ جوائز مع كود استلام، و**شهادة تقدير لكل سورة** تُرسم على canvas وتُحمَّل PNG أو تُطبع أو تُشارك.
- **إعدادات كاملة**: الاسم والصورة الرمزية، مقدار الورد، المؤثرات الصوتية، الوضع الليلي، تغيير كلمة المرور، تصدير/استيراد نسخة احتياطية JSON، إعادة تعيين التقدم، وحذف الحساب وكل بياناته من السحابة.

## قاعدة البيانات السحابية (Supabase)

| الملف | الوظيفة |
|---|---|
| `supabase/schema.sql` | كود SQL كامل: جداول `kids_profiles` و`kids_progress`، الفهارس، triggers، سياسات RLS، ودالة حذف الحساب. يُنفَّذ مرة واحدة من **SQL Editor**. |
| `supabase/README.md` | خطوات الإعداد: إنشاء المشروع، تشغيل SQL، تعطيل تأكيد البريد، ضبط روابط الاستعادة، واختبار الأمان. |
| `supabase-config.js` | إعداد عام: `url` + `anon` key فقط. **لا يضع فيه `service_role` أبدًا.** |
| مكتبة العميل | `@supabase/supabase-js@2.118.0` من jsDelivr، وتُخزَّن في Service Worker لتعمل دون اتصال. |

**ملاحظة أمنية:** مفتاح `anon` مفتاح عام (publishable) بطبيعته في أي موقع ثابت؛ الحماية الحقيقية من **RLS** في قاعدة البيانات. يمكن إبقاء المفتاح خارج المستودع بحقنه وقت النشر من أسرار GitHub:
`SUPABASE_URL` و`SUPABASE_ANON_KEY` في **Settings → Secrets and variables → Actions**. سير النشر يكتبهما في `_site/supabase-config.js` تلقائيًا عند توفرهما.

## تطبيق الجوال (PWA)

الموقع يعمل كتطبيق قابل للتثبيت على الجوال، ويُخزَّن هيكله (HTML/CSS/JS والخطوط) للعمل **دون إنترنت** بعد أول فتح. في تطبيق الأطفال: يُعرض آخر تقدم محفوظ على الجهاز أثناء انقطاع الشبكة، ويُزامَن تلقائيًا عند عودتها؛ أما أول تسجيل دخول وتلاوة الحصري فتحتاج إنترنت.

| الملف | الوظيفة |
|---|---|
| `manifest.webmanifest` | بيانات التطبيق: الاسم، الاتجاه RTL، الأيقونات، اختصارات الوصول السريع (رحلة الحفظ / الاختبارات / السور). |
| `sw.js` | Service Worker: يخزّن كل ملفات الموقع والخطوط، ويعمل دون اتصال. |
| `pwa.js` | تسجيل Service Worker + زر «ثبّت التطبيق» + تنبيه «توجد نسخة جديدة». |
| `icons/` | أيقونات 192 و512 وmaskable وapple-touch. |

> ⚠️ عند تعديل أي ملف من قائمة `CORE` داخل `sw.js`، ارفع قيمة `VERSION` (مثلًا `juz-amma-v7` ← `v8`) حتى يستلم الزوار النسخة الجديدة. ملف `supabase-config.js` مستثنى لأنه يُقرأ من الشبكة أولًا.

**التثبيت على الجوال:**
- **أندرويد (Chrome/Edge):** يظهر شريط «ثبّت التطبيق» أسفل الصفحة، أو من القائمة ⋮ ← «تثبيت التطبيق».
- **آيفون/آيباد (سفاري):** زر المشاركة ← «إضافة إلى الشاشة الرئيسية».
- بعد التثبيت يفتح التطبيق بلا شريط عنوان، ومعه اختصارات: «رحلة الحفظ» و«الاختبارات» و«السور».

## النشر على GitHub Pages
يُنشر الموقع تلقائيًا باستخدام GitHub Actions عند كل تحديث لفرع `main`، كما يمكن تشغيل النشر يدويًا من تبويب **Actions**.

1. أنشئ مشروع Supabase ونفّذ [`supabase/schema.sql`](supabase/schema.sql)، ثم اضبط `supabase-config.js` أو أضف السرّين `SUPABASE_URL` و`SUPABASE_ANON_KEY` إلى المستودع (التفاصيل في [`supabase/README.md`](supabase/README.md)).
2. أنشئ مستودعًا على GitHub وارفع ملفات المشروع إلى جذر الفرع `main`، مع مجلد `.github/workflows` وملف `.nojekyll`.
3. في المستودع، افتح **Settings → Pages**، واختر **GitHub Actions** كمصدر للنشر.
4. ادفع التغييرات إلى `main` أو شغّل سير العمل **Deploy to GitHub Pages** يدويًا من **Actions**.
5. بعد نجاح التشغيل، افتح الرابط الظاهر في سجل سير العمل أو في **Settings → Pages**. عادةً يكون `https://USERNAME.github.io/REPOSITORY/`.

إذا كان اسم الفرع الافتراضي مختلفًا عن `main`، غيّر قائمة الفروع في `.github/workflows/pages.yml` لتطابقه. لا يحتاج الموقع إلى إعداد مسار أساسي خاص بالمستودع؛ جميع موارده محلية وبمسارات نسبية. تقدم تطبيق الأطفال محفوظ في Supabase، أما سجل اختبارات التفسير و«ختمة التدبّر» فما زالا محليين في المتصفح.
